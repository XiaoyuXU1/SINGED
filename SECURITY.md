# Security and privacy

SINGED is designed for controlled evaluation with synthetic data. The bundled
functional counterfeits perform only five local, auditable effects: a loopback
receipt, an out-of-scope marker write, a read of a synthetic unrelated file, a
change to synthetic protected metadata, or a trivial subprocess.

## Before publishing or sharing results

Run:

```bash
python scripts/check_release.py
```

The check rejects common API-key formats, private keys, local user paths,
cloud-sync paths, and messaging identifiers. Before a release, private
development terms can be supplied locally through the comma-separated
`SINGED_PRIVATE_TERMS` environment variable; never commit its value. Generated
runs and `.env` are excluded from Git.

## Credential handling

- Store only `OPENROUTER_API_KEY` in `.env` or the process environment.
- Never put credentials in JSON configuration, command arguments, manifests,
  issue reports, or trace files.
- Revoke a key immediately if it is ever committed, even if the commit is later
  removed.

## Execution boundary

The runner executes only benchmark-generated archives whose SHA-256 hashes match
the manifest. Archive paths are checked before extraction and no shell is used.
This is still not a general untrusted-code sandbox. Use an isolated container or
virtual machine before testing packages not generated by this repository.

## Reporting a vulnerability

During anonymous review, report security issues through the repository's private
security-advisory channel. Do not include real credentials, personal data, or
private user files in a report.
